Major: test/unit/after_callbacks_test.rb:53-75
The tests intended to exercise after_save callbacks often save records without any changes. In Rails 7+/8+, ActiveRecord skips save/update callbacks when there are no changes (unless touch is forced). You only set updated_on for some models; many of the observables (e.g., IssueRelation, Member, Attachment, Project, WikiContent, TimeEntry) do not have updated_on and thus .save will be a no-op, never running the plugin’s after_save hook. This can produce false failures (callbacks not run, errors empty) or, worse, false confidence if the assertion doesn’t actually exercise the code path.
Concrete failure: For IssueRelation.find(1), relation has no updated_on; object.save returns true without running callbacks, so object.errors[:base] remains empty and assert_includes object.errors[:base], 'after_save failed' fails even though the plugin behavior is correct.
Fix: Ensure a real update is performed for every tested model.
- Simplest: call object.save(touch: true) (forces timestamp update and runs callbacks) and use it consistently in both after_save tests.
- For models without timestamp columns, change a safe attribute before save:
  - IssueRelation: object.delay = (object.delay.to_i + 1)
  - Attachment: object.description = 'x'
  - Member: object.mail_notification = 'only_my_events' (or toggle false/true as appropriate)
  - Project: object.homepage = 'x'
  - WikiContent: object.comments = 'x'
  - TimeEntry: object.comments = 'x' or object.hours += 0.1
  - Version: object.description = 'x'
Apply the same change in test_raising_after_save_keeps_the_saved_... as well. Example:
  object.assign_attributes(description: 'x') if object.respond_to?(:description)
  assert object.save(touch: true), "#{observable} not saved"

Resolution: not a defect. Active Record runs the save callbacks even when nothing changed (only the UPDATE statement is
skipped). Proven by the tests themselves: they assert the error the after_save script added, and before dbdcf48 29 of
the 30 failed with UncaughtThrowError raised from inside after_save_custom_workflows, which only happens when the
callback runs.
