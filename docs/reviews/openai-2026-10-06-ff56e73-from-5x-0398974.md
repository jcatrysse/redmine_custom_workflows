Major: app/views/custom_workflows/_form.html.erb:74,89,107,130
Problem: Misuse of sprite_icon API. The helper in Redmine 7 takes (name, text = nil, options = {}); passing rtl: collapsed as the second argument is interpreted as the text, so the hash gets stringified and rendered, and the options are not applied. The angle icon may not render and “{:rtl=>true/false}” can appear in the legend.
Scenario: Open the custom workflow form. The collapsible fieldset legends display garbage text like “{:rtl=>true}” and the expand/collapse chevrons don’t show correctly, making the UI confusing.
Fix: Pass nil for the text argument and supply options as the third argument: 
- <%= sprite_icon(collapsed ? 'angle-right' : 'angle-down', nil, rtl: collapsed) %>
If rtl is not a supported option in your Redmine, omit it entirely and keep only the first argument.

Resolution: not a defect. Redmine 7 `sprite_icon(icon_name, label = nil, ..., rtl: false)` takes `rtl` as a keyword
(app/helpers/icons_helper.rb:36), exactly how core calls it in workflows/edit.html.erb. The functional test
`test_edit_collapsible_legends_have_svg_icons` asserts the `svg.icon-rtl use[href$="#icon--angle-right"]` markup and the
screenshots admin_crud-edit-form / admin_crud-legend-open show the arrows and no stray text.

Major, test/unit_test.rb:23
Problem: The UnitTest base class overrides initialize to load all plugin fixtures on every test instance via ActiveRecord::FixtureSet.create_fixtures. This bypasses Rails’ fixture/transaction management and reloads/drops tables repeatedly per test instance. It is unsafe under parallel test execution (possible deadlocks/data races on MySQL/MariaDB) and can cause non-deterministic isolation because the reload happens outside the per-test transaction.
Failure scenario: Run the plugin test suite with parallelization enabled (e.g., MINITEST_PARALLEL or a CI runner), two tests executing concurrently both hit initialize and attempt to delete/insert the same plugin tables, leading to deadlocks (InnoDB) or random failures (“Deadlock found when trying to get lock” / “Duplicate entry”).
Fix: Revert to controlled, class-level fixture loading:
- Restore the previous fixtures(*table_names) override and keep explicit fixtures declarations in test classes; or
- Use ActiveSupport::TestCase.fixtures to declare required core fixtures and load plugin fixtures once per test class in setup_once/before_setup, within Rails’ fixture framework; or
- If you must auto-load plugin fixtures, do it once per test run (e.g., in test_helper before tests start) and not per test instance, and wrap it in Rails fixture loading (FixtureSet) that participates in transactional tests.

Resolution: not changed. Upstream test infrastructure (unchanged by this branch); the suite does not run in parallel
(test_plugin.sh loads all files in one process) and is green on PostgreSQL and MariaDB. Recorded in the plan as an
upstream improvement, not a migration item.
